# 代理列表批量 e2e 测试

命令 `cmd/proxy-e2e` 按轮次执行以下流程：

1. 读取代理列表，为每个代理分配独立的 bridge 端口并调用 `/bridge/add`。
2. 只有 add 成功的桥进入请求阶段；使用 worker pool 并发访问 `http://myip.ipipv.com/`。
3. 解析响应中的 `Ip` 字段。同一代理在同一轮的多次请求必须返回同一个出口 IP；不一致归类为 `ip_mismatch`。
4. 调用 `/bridge/del` 删除本轮所有分配的 bridge 端口，并检查端口不再接受连接。
5. 轮数大于 1 时重复上述流程。

## 代理文件格式

TXT：每行一个代理，支持：

```text
socks5://username:password@198.51.100.10:1080
http://username:password@198.51.100.11:8080
198.51.100.12:1080
```

CSV：第一列为完整代理地址，首行为 `proxy`、`proxy_url` 或包含“代理”的表头会跳过，其余列忽略：

```csv
proxy,source
"socks5://username:password@198.51.100.10:1080",vendor-a
```

代理地址支持 `socks5://`、`socks5h://` 和 `http://`。当前服务的 `/bridge/add` 要求 IP，代理主机为域名时命令会先 DNS 解析为 IP；DNS 失败单独归类为 `add_proxy_resolve`。

## 运行

从仓库根目录执行：

```powershell
go run ./cmd/proxy-e2e `
  -proxy-file D:\work\data-1788313833471.csv `
  -rounds 1 `
  -concurrency 10 `
  -requests-per-proxy 2 `
  -report D:\work\proxy-e2e-report.json
```

参数：

| 参数 | 缺省 | 说明 |
|---|---:|---|
| `-proxy-file` | 必填 | TXT 或 CSV 代理列表 |
| `-rounds` | 1 | 测试轮数 |
| `-concurrency` | 10 | 最大并发请求数 |
| `-requests-per-proxy` | 2 | 每个代理每轮请求数，用于验证出口 IP 一致性 |
| `-request-timeout` | 25s | 单请求超时 |
| `-bridge-bin` | 自动构建 | 指定待测 bridge-direct 二进制 |
| `-report` | 空 | 输出 JSON 明细报告 |
| `-verbose` | false | 输出每个代理的 add/request/del 明细 |
| `-dry-run` | false | 只解析文件，不启动 bridge 和发请求 |

命令退出码：所有 add、请求、IP 一致性和删除校验都通过时为 `0`；任一失败时为 `1`；参数或文件格式错误时为 `2`。

运行过程中会持续输出：

```text
proxy-e2e loaded 94 valid proxies
round=1/1 phase=add start total=94
round=1 phase=add progress=1/94 status=ok bridgePort=31805 proxy=#1 198.87.99.213:30465
round=1 phase=request start total=188 concurrency=10
round=1 phase=request progress=10/188 class=success proxy=#5 103.224.253.92:8112 ip=103.224.253.92
round=1 phase=del progress=94/94 status=ok bridgePort=31903 proxy=#94 182.40.197.170:2018
```

请求阶段默认每完成 10 个请求打印一次；失败请求立即打印，因此长时间没有汇总时也能判断当前卡在 add、请求还是 del 阶段。

敏感信息不会写入日志或报告，报告中的代理标识只包含主机和端口。
