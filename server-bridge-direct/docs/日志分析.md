# bridge-direct 日志与观测说明

当前实现统一使用结构化 `slog` 记录启动、管理 API、监听、同步、转发和资源水位。连接流量使用 `Debug`，默认 `Info` 级别不会按连接刷日志；文件日志由 lumberjack 负责轮转。

## 日志输出

| 配置 | 说明 |
|---|---|
| `logFile` | 文件日志路径；为空时只输出到 stdout，需由 journald、容器运行时等负责限额 |
| `logConsole` | 配置了 `logFile` 时是否同时输出到控制台 |
| `logLevel` | `debug`、`info`、`warn`、`error`，缺省为 `info` |
| `logFormat` | `text` 或 `json`，缺省为 `text` |
| `logSource` | 是否记录代码位置 |
| `logMaxSizeMB` | 单个日志文件大小上限，缺省 100 MB |
| `logMaxAgeDays` | 归档保留天数，缺省 7 天 |
| `logMaxBackups` | 归档保留份数，缺省 10 份 |
| `logCompress` | 是否压缩归档，缺省开启 |

## 事件覆盖

### 生命周期

- `bridge-direct starting` / `shutting down`：版本、模式和退出信号。
- `bridge-direct startup ...`：始终输出到 stdout 的版本、构建时间和 Git 提交，用于启动时确认构建版本；不受 `logFile`/`logConsole` 影响。
- `management server listening`：管理服务监听地址。
- `SetBridgeHandler start/retarget`：桥创建或原子切换目标。
- `listen` / `accept loop closed` / `DelBridgeHandler`：监听建立和下线。
- `pprof listening`：pprof 地址和常用路径提示。

### 错误路径

- `AddBridge` / `DelBridge` / `StartBridge`：解密、校验、监听、持久化、恢复和回滚失败。
- `syncBridge start`：同步开始时立即记录中心地址和 bridgeId，避免网络超时期间没有日志。
- `syncBridge ok`：同步成功时记录桥数量和耗时。
- `syncBridge failed`：网络错误、非 200 响应、响应解析和缓存替换失败，包含耗时与 `timeout` 标记。
- `bind failed, retrying` / `accept failed, retrying`：监听异常与退避时间。
- `dial target`：来源地址、目标地址和拨号错误。
- `dump create/write/sync/rename`：缓存文件原子写入失败。

管理 API 兼容现有协议：业务失败返回 JSON `code=500`，HTTP 状态仍为 200。服务端日志会记录对应错误及端口、目标、来源 IP 等上下文。

### 流量与资源

- `flow-up` / `flow-down`：`Debug` 级别，包含 `srcaddr`、`toAddr`、`amount` 和 `err`。
- `stats`：配置 `statsInterval` 后周期输出，且 `GET /bridge/status` 响应顶层也返回同一快照；字段包括 goroutine、桥数量、监听数、在途连接、累计接收/拒绝、拨号结果、堆和 GC 水位。

## 字段约定

```text
port=9000 toAddr=1.2.3.4:80 srcaddr=10.0.0.2:50000 amount=1234 err=<error>
```

常用字段：

| 字段 | 含义 |
|---|---|
| `port` | 桥监听端口 |
| `toAddr` | 转发目标地址 |
| `srcaddr` | 客户端来源地址 |
| `clientIP` | 管理 API 调用方 IP |
| `amount` | 单方向转发字节数 |
| `listening` / `bridges` / `conns` | 监听与连接水位 |
| `accepted` / `rejected` | 累计接收和限额拒绝数量 |
| `dialOK` / `dialFail` | 目标拨号结果 |
| `err` | 错误对象 |

## 运维建议

1. 生产环境保持 `info`，排查单连接问题时临时切换为 `debug`。
2. 开启 `statsInterval` 观察连接、拒绝、拨号和内存是否单调增长。
3. `pprofAddr` 只能绑定回环或可信内网；pprof 没有鉴权，会暴露进程内存和调用栈。
4. 同时开启 `logFile` 和 `logConsole` 会产生双份日志，stdout 那份不受 lumberjack 轮转限制。
